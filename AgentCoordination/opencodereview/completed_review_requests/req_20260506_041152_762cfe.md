## Instructions

Focus areas (in priority order):

1. **Cache invalidation correctness.** The cache key is `(round(camera.position.x, 1), round(camera.position.y, 1), round(camera.zoom, 2), viewport_w, viewport_h, hex_size)`. Walk through every input that the inner `draw_grid` reads from `r` and confirm each is either in the key or provably constant for cache lifetime. Specific concerns to check:
   - Does `draw_grid` read any global state, theme, or color that could change without invalidating the cache?
   - Hex orientation / hex spacing constants — fixed or configurable?
   - Camera-related fields beyond position+zoom (rotation, viewport offset)?
   - The `r` parameter is the `StrategyRenderer` — does it expose mutable state used by grid rendering that's not in the key?
   - Sub-quantum jitter tolerances (position 0.1 world-units, zoom 0.01) — are these visually safe? Could pan/zoom motion at speeds that align with these quanta produce a stale grid relative to the rest of the scene?

2. **Memory safety.** 
   - Surface allocation: `pygame.SRCALPHA` viewport-sized, allocated once, reused via `fill((0,0,0,0))`. Does the `fill` actually clear all pixels including the alpha channel?
   - Viewport-resize path: when does the surface get reallocated? Is there a leak risk on rapid window resizes?
   - Reference cycle / lifetime: does `GridLayer` hold a reference to the renderer that would prevent GC?

3. **Concurrent access.** Pygame rendering is single-threaded by convention but verify nothing in `GridLayer` would break if called from a non-main thread. (Likely a no-op finding; flag if anything looks risky.)

4. **Test coverage gaps.** The 17 cases cover identity, per-input invalidation, sub-quantum jitter, surface management. What input variation could miss the cache key without triggering a test failure? Specifically:
   - Are there inputs read by `_render_grid_to_surface` that aren't parametrized in the invalidation tests?
   - Is the zoom-at-cutoff transition (0.39 → 0.41 → 0.39) tested? 
   - Multiple consecutive viewport resizes?
   - Test fixture realism: tests use a stub renderer — do its attributes match the production renderer's surface? Is anything missing that production code touches?

5. **Pattern consistency.** Compare to `BackgroundLayer` (`background.py:17-58`) and `HexOutlineLayer` (`hex_outlines.py:20-80`). Specifically:
   - Surface flags / pixel format consistency
   - Cache invalidation idiom (key tuple vs. dirty flag vs. version counter)
   - Naming conventions (`_cache_key`, `_cached_surface`, etc.)
   - Edge cases the existing layers handle that GridLayer doesn't
