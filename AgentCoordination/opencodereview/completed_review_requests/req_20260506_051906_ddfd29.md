## Instructions

Focus areas (ordered by importance):

1. **Phase 1 cache correctness** (commit `d68c39805`).
   - Cache key is `(design_id, file_mtime_ns)`. The fingerprint comes from `os.stat(get_design_path(design_id)).st_mtime_ns`. What happens if the design file is deleted? Renamed? Saved twice within filesystem mtime resolution (Windows NTFS = 100ns; macOS HFS+ = 1s)? Could a save-then-quick-resave produce an identical mtime and cause the cache to serve the stale validation result? Walk through the save path in `game/strategy/systems/design_library.py:184` `save_design`.
   - Lazy `DesignValidator` construction: confirm zero cost on pure cache hits. Check that the validator instance survives across calls (one-time construction per controller).
   - The new `reset_filters()` public method exists for Phase 2's yard-switch path. Phase 2 didn't ship — is `reset_filters()` reachable from any current code path, and if so does it behave correctly? If unreachable, is it dead code today?
   - Tests: are the 13 cache tests genuinely covering invalidation scenarios (modify file → cache misses) or only covering the happy path?

2. **Phase 3 row-pool rebuild guard** (commit `aca743a25`).
   - The guard short-circuits `_rebuild_row_pool` when panel dimensions are unchanged AND a pool already exists. Walk through every code path that calls `_rebuild_row_pool` and confirm none of them rely on a side-effect of the rebuild (e.g., row-state reset, column-config change) that the new guard might suppress.
   - The 4 new tests cover dim-change/no-change/initial-build/post-clear cases — what edge cases are missing? Specifically: column-count change without dimension change? Row-style change? Theme reload?
   - Phase 3 says the guard "pays off ~1.5s/click once Phase 2 lands later" — is that claim quantitatively defensible from the profile evidence at `findings/profile_summary.md`?

3. **Phase 4 scoped `@fast_panel`** (commit `8df0b40e2`).

   - Are there other panel-construction sites in the build-queue module (not in the factory) that also need `@fast_panel`?
   - Theme block correctness: does the new block override only the shape, leaving inherited colors / border / focus styles intact? A wrong override could regress visual design.
