## Instructions

## Instructions

**Primary focus areas:**

1. **Pattern #5 facade bypass eradication is the CRITICAL win.** The fix has TWO halves: (a) privatize `strategy_screen.session` → `_session` AND (b) remove the fallback dispatch sites in build_queue_screen / empire_build_queue_window. Both are required. The agent kept a writable `session` property setter to preserve test mocks, claiming 'the static guard catches the dispatch regression that mattered.' Verify:
   - The static-guard at `tests/static_guards/test_facade_bypass_guard.py` actually fails on the original violation. Reproduce by reverting Phase 1 commits locally OR by reading the AST scan logic to confirm it would catch `<expr>.session.handle_command(...)`.
   - Does the writable property setter open a hole for production code to do `screen.session = some_other_session` and then call `.handle_command(...)`? If yes, the static-guard must catch that path too, not just the original.
   - The new `get_registries()` on `StrategySessionFacade` — is it the canonical access path now, or is registries also reachable through some other route that didn't get migrated?

2. **`BuildQueuePortraitLoader` `portrait_session=` kwarg.** Agent introduced this 'narrow read-only handle' as a workaround because the loader needs `active_empire.empire_theme_id`. This sounds dangerously close to a re-export-shim it just documented in Pattern #36. Is it (a) a legitimate narrow type that genuinely encapsulates only the read needed, or (b) a backdoor that hands the full session through under a new name? If (b), it's a Rule 3 violation that the static-guard should catch but doesn't (because the guard only fires on `session.handle_command(...)`).

3. **`builder/event_bus.py` rename to `WorkshopEventBus` (15 imports).** Verify by grep that no import of the old `EventBus` from `builder/event_bus` remains anywhere in the repo (production OR tests). A missed import would silently fall back to the canonical strategy `EventBus` and lose workshop-scope subscription semantics.

4. **`production_spawner.py` `registries=` required kwarg.** Required AND eager. Confirm:
   - All call sites pass `registries=` explicitly (no default propagation through ApplicationContext that lets a None slip through).
   - The eager `planet_mutator` injection in `__init__` doesn't break tests that previously instantiated the spawner without a mutator and only used it for spawn-spec generation.

5. **Phase 5 file splits — true decomposition vs cosmetic line moves.** The agent claims 8-sub-module decomposition of `planetary.py`. Spot-check 2-3 of the sub-modules:
   - Are the boundaries semantically meaningful (one ability per module / coherent grouping by responsibility)?
   - Or did they cut along arbitrary line counts and re-import everything via the package `__init__.py` such that the public API is identical and you've just moved code around?
   - Pattern #36 (the new Re-Export Shim entry) explicitly warns against this anti-pattern; if the package `__init__.py` reads like a 59-line re-export list, that's a signal.

6. **Deferred Task 5.4 (`superweapon_order_processor.py` 723 LOC).** Agent logged this with 'extracting closures requires a state-bag type or threading engine refs through every closure' rationale. Read the file briefly:
   - Is the rationale honest (5 dispatchers genuinely closure over engine state)?
   - Or could a straightforward extraction (e.g., `class _SuperweaponDispatcher` with the state as instance fields) have done it?
   If a straightforward path exists, this is a remediation candidate, not a real architectural deferral.

7. **`docs/02_PATTERNS.md` Pattern #36 (new, Re-Export Shim).** Verify:
   - Section follows the template of neighboring patterns (problem, structure, when to use, when not to use, examples, retirement).
   - The 'when not to use' section explicitly addresses the Pattern #5 facade-bypass case so PROJ-382's own Phase 1 work doesn't re-emerge as a 'Re-Export Shim is fine' rationale in 6 months.
   - Pattern #23 phase list reconciliation actually matches the 6-phase reality; if it still lists 5, the doc drift wasn't fixed.

8. **PROJ-381 cross-impact.** PROJ-381 (just merged, 6 commits) added new exceptions to `game/core/exceptions.py` and edited `turn_engine.py` / `game_session.py`. PROJ-382's Phase 3 also touches `game_session.py` (tautology guard). Verify the two changes don't conflict:
