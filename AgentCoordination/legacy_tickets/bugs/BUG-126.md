# BUG-126: Strategy-layer combat draw silently destroys the smaller fleet — `_resolve_winner_team` survivor-count tiebreaker treats `BattleOutcome.winner=None` as a winnable contest

## Description

Two fleets entered the same hex on the strategy map and combat
"resolved", but the surviving ship had ZERO weapons (no beams, no
projectiles — only Bridge / Crew Quarters / Life Support / Generator /
Standard Engine / Warp Drive / Fuel Tank / Battery). The user expected
this ship to be destroyed by the opposing fleet, which presumably had
weapons. Instead it survived and the opposing fleet was destroyed.

The Combat Record on the survivor reads **"Battles Survived: 1, Kills:
0, Experience: 0"** — kills=0 is the smoking gun. If the simulator
actually ran and this ship survived because it killed everything, kills
should be >0. kills=0 + battles-survived=1 means this ship won without
firing a shot.

User commentary at QA Session 20260428_190154 [19:23:10 – 19:24:20]:
> "I've had combat occur with what I think are ships that do not have
> weapons. Yeah they don't have any weapons and yet for some reason
> they were able to kill the other ships. So I'm questioning whether
> the real-time combat is actually occurring. I know at one point we
> had a bypass where it would just randomly pick a winner and delete
> the other fleet — I do not think that's what's happening. It even
> says battle survived as 1, kills as 0, which is weird because if
> kills are zero then I don't know how they won."

## Code investigation findings

The strategy → simulation entry path is:
1. [`ConflictResolutionEngine._resolve_combat_at_hex()`](../../../game/strategy/engine/conflict_resolution_engine.py#L222)
2. → [`SimulationBattleResolver.resolve_battle()`](../../../game/strategy/adapters/simulation_adapter.py#L66)
3. → `run_battle(spec, ...)` (real `BattleEngine` simulator).

**Three shortcut paths bypass the simulator:**

1. **Empty fleets** ([simulation_adapter.py:116-121](../../../game/strategy/adapters/simulation_adapter.py#L116-L121))
   — all teams have zero combat-capable ships → no winner.
2. **Sole survivor** ([simulation_adapter.py:122-137](../../../game/strategy/adapters/simulation_adapter.py#L122-L137))
   — only one team has *any* combat-capable ships → auto-wins
   without simulation. **Most likely culprit.**
3. **RNG empty-fleet edge case** ([simulation_adapter.py:298-310](../../../game/strategy/adapters/simulation_adapter.py#L298-L310))
   — no fleets have any ships → RNG picks a winner.

The `is_combat_capable` definition ([ship_instance.py:310-312](../../../game/strategy/data/ship_instance.py#L310-L312))
is `is_alive AND NOT is_derelict` — **does not check for weapons**.
A weaponless escort with full HP is "combat-capable".

## Open questions for the fix engineer

If the sole-survivor shortcut fired, then the opposing fleet had **no**
combat-capable ships at the moment `resolve_battle()` ran — meaning
the entire opposing fleet was already `is_alive=False` or
`is_derelict=True`. Possible upstream causes:

1. **Pre-combat state corruption** — were the opposing ships flagged
   derelict by some prior tick / event before the resolver ran?
2. **Spec materialisation drift** — does
   `_build_battle_spec()` produce ships with wrong `is_alive` /
   `is_derelict` flags from the spec → instance materialisation?
3. **Empty-target fleet** — was the opposing "fleet" actually a
   colony / cargo fleet whose ships are flagged differently?
4. **Race condition** — could a fleet have lost ships in a separate
   resolution tick at the same hex earlier in `_resolve_combat_at_hex`?

If the simulator DID run (no shortcut), then:

5. **Simulation timeout draw** — what does `BattleEngine` return when
   neither side has weapons and `max_ticks` elapses? Does it pick a
   "winner" by HP / mass / something else? If so, the weaponless
   escort tied or won that tiebreaker.
6. **Damage-source mis-attribution** — kills=0 on the survivor could
   mean the opposing fleet's ships died to environmental hazards,
   self-destruct, or out-of-fuel/energy starvation.

## Repro steps (user-facing)

The user did NOT explicitly reproduce — combat occurred during normal
play. The bug-reproducer needs to:
- Construct a scenario where a fleet of weaponless ships meets an armed
  fleet at a hex.
- Confirm whether combat enters the simulator or a shortcut.
- Inspect `is_alive` / `is_derelict` on every ship in the spec at the
  moment of `resolve_battle()` invocation (log it in
  `SimulationBattleResolver.resolve_battle` between the spec build and
  the shortcut-evaluation).
- Run the resolver under `pytest -s -k weaponless` with
  `caplog.at_level("DEBUG", "game.strategy.adapters.simulation_adapter")`
  to capture which branch fires.

## Suggested fix path (not prescriptive)

1. **Add diagnostics first.** Before changing logic, instrument
   `SimulationBattleResolver.resolve_battle()` to log which branch
   fires (shortcut #1 / shortcut #2 / shortcut #3 / real simulator).
   Re-run the user's save to confirm the branch.
2. **Replay capture metadata.** Even when a shortcut fires, the
   `_build_capture_context` should still emit a record so the Event
   Log shows "battle resolved (sole survivor)" rather than appearing
   as if a real fight took place.
3. **`is_combat_capable` may be insufficient.** Consider replacing
   the sole-survivor shortcut's gating predicate with one that also
   checks whether the team has at least one *armed* ship — otherwise
   a fleet of weaponless transports auto-wins against a destroyed
   armed fleet. A weaponless team should still be eligible to lose
   if there's a draw rule.
4. **Tests.**
   - `tests/integration/strategy/test_combat_shortcut_paths.py`:
     scenarios for each shortcut, asserting which branch fires and
     whether `BattleResult.victor` is correct in each.
   - Specific scenario: weaponless escort vs armed escort. Assert the
     simulator runs (no shortcut) and the armed ship wins.

## Acceptance

- A weaponless ship cannot win a strategy-layer combat against an
  armed enemy fleet.
- The shortcut-path branch decisions in
  `SimulationBattleResolver.resolve_battle` are logged at DEBUG so
  future cases are diagnosable from `battle.log`.
- Combat Record (`Kills` / `Battles Survived`) on the surviving ship
  is consistent — kills=0 only when the simulator timed out or the
  survivor genuinely never fired.

## Priority

High — this directly contradicts player expectation about how combat
works. Combined with the unrelated "no replay visible" symptom from
the same observation (covered by FEAT-26), the user reasonably
suspects "real-time combat is not occurring" — and that perception
will undermine confidence in the entire combat layer until resolved.
