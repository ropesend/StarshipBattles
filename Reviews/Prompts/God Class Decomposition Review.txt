### What Agents Should Investigate Per File

For EACH target file, agents should determine:

1. **Responsibility inventory:** List every distinct responsibility the class handles
2. **Extraction candidates:** Which responsibilities can be extracted and into what classes?
3. **Dependency analysis:** What depends on this class? What would break during extraction?
4. **Extraction pattern:** Which pattern fits best? (facade/delegate, MVVM, renderer extraction, strategy, mixin, composition)
5. **Estimated reduction:** What's the realistic target line count after decomposition?
6. **Test impact:** How many tests touch this class? What test changes are needed?
7. **Risk assessment:** What's the risk of regression during extraction?
8. **Accept/Decompose verdict:** Some files may be acceptable at their current size (e.g., StrategyRenderer is a focused renderer). Agents should explicitly recommend "accept" for files that don't need decomposition.

---

### Special Investigation: Re-Offender Analysis

For the 3 re-offender files (TestLabScreen, BuildQueueScreen, EmpireBuildQueueWindow):

1. **What was extracted by PROJ-86/89?** Read the extraction history.
2. **What grew back?** Diff the responsibilities — what new code was added after extraction?
3. **Why did it grow back?** Was it new features? Was the extraction boundary wrong? Was the delegate pattern insufficient?
4. **What would prevent regrowth?** Recommend specific guardrails:
   - CI line-count checks (fail build if file exceeds threshold)?
   - Architectural rules (new features must go in delegates, not the main class)?
   - Code ownership / review gates?
   - Automated complexity metrics (cyclomatic complexity threshold)?

---

### Special Investigation: Growth Prevention Mechanisms

Beyond the re-offender analysis, agents should recommend **proactive guardrails** for the entire codebase:

1. **Line count CI check:** Should there be a max-lines-per-file threshold in CI? What threshold? (500? 600? 800?)
2. **Method count check:** Should there be a max-methods-per-class check?
3. **Complexity metrics:** Should cyclomatic complexity be measured and gated?
4. **Architecture Decision Records:** Should decomposition decisions be formally documented to prevent drift?
5. **Import count heuristic:** Files with >20 imports are often god classes — should this be flagged?
