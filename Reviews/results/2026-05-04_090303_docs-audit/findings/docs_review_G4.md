## Dead Reference Findings (manual, non-game/* paths)

### Finding 1: `AgentCoordination/Scratchpad/` referenced but does not exist (MAJOR)
- **Doc files:** AGENTS.md:80, CLAUDE.md:160, CLAUDE.md:172
- **Evidence:** `AgentCoordination/` exists with subdirectories `generated/`, `opencodereview/`, `protocols/`, but no `Scratchpad/` directory. The `SCRATCHPAD.md` file exists at `AgentCoordination/SCRATCHPAD.md` and describes this directory structure, but the directory itself was never created.
- **Impact:** Both AGENTS.md and CLAUDE.md instruct agents to write transient files to `AgentCoordination/Scratchpad/` subdirectories (`plans/`, `reviews/`, `reports/`, `handoffs/`, `tmp/`). An agent following these instructions would either create the directory on first write or error out depending on how it handles missing directories. Either way, the convention is documented but the infrastructure isn't in place.
- **Proposed:** Either create the `Scratchpad/` directory with its subdirectories and `.gitkeep` files, or update the docs to acknowledge it may not exist and instruct agents to create it on first use.

### Finding 2: `.test_durations.json` referenced but does not exist (MINOR)
- **Doc files:** AGENTS.md:69
- **Evidence:** No `.test_durations*` files exist at the repo root. This file is described as the source for "greedy load balancing" in the sharded test runner.
- **Impact:** The sharded test runner likely falls back gracefully (auto-detects CPU count without duration data), so this is not a breaking issue. However, the doc implies first-run behavior differs from described behavior until this file is generated.
- **Proposed:** Document that this file is auto-generated by the test suite on first run, or verify it gets created after a full suite execution.

### Finding 3: Protocol 08 references retired loop runner scripts (MINOR)
- **Doc files:** Projects/protocols/08_automated_loop_protocol.md:312
- **Evidence:** References `loop_runner.ps1` and `loop_runner.sh`. Both files are absent from the repo. The protocol itself carries a status note (line 7-11) stating the loops were retired.
- **Impact:** The protocol is preserved as reference; the dead script references are internally consistent with the retired status. A reader skimming the file could be confused.
- **Proposed:** Add a `~~strikethrough~~` or `<!-- comment -->` around the loop runner references to visually signal they are retired, consistent with the status banner at the top.

### Finding 4: Python version inconsistency between AGENTS.md and CLAUDE.md (MAJOR)
- **AGENTS.md:52:** "Python 3.14"
- **CLAUDE.md:94:** "Python 3.13+"
- **Actual runtime:** `python --version` returns `Python 3.14.2`
- **Impact:** AGENTS.md is correct; CLAUDE.md is outdated. An agent reading only CLAUDE.md could target 3.13-compatible syntax where 3.14 features are available, or vice versa if it reads AGENTS.md first then sees the CLAUDE.md override. ## Project Protocol Findings

### Finding 10: Retired protocols lack visual distinction (MINOR)
- **Files:** `Projects/protocols/08_automated_loop_protocol.md`, `Projects/protocols/10_manage_refactor_plan.md`
- Both protocols carry internal status banners indicating they are "preserved for reference" after the retirement of their associated loop systems. However, they appear in the directory listing alongside active protocols with no naming convention or index marker to distinguish them.
- **Impact:** An agent browsing `Projects/protocols/` would need to open and read each file to discover which are retired. The `WORKER_TEMPLATE.md` (line 189) lists Protocol 08 as "Primary" — if a worker actually follows that instruction, it would enter a retired workflow.
- **Proposed:** Either rename retired protocols with a `_RETIRED_` prefix, move them to a `retired/` subdirectory, or add a prominent index marker in a README for the protocols directory.

### Finding 11: Protocol 08 WORKER_TEMPLATE.md dependency on a retired protocol (MINOR)
- **File:** `Projects/protocols/WORKER_TEMPLATE.md:189`
- References `Projects/protocols/08_automated_loop_protocol.md` as "Primary" protocol.
- **Impact:** If this template is still used (its `> This is a shared template` banner doesn't mark it as retired), workers would follow a retired workflow.
- **Proposed:** Either retire the WORKER_TEMPLATE.md as well, or update its primary protocol reference to the active workflow.

### Finding 12: Protocol 03c references `AgentCoordination/opencodereview/local/` subdirectory (INFORMATIONAL)
- **File:** `Projects/protocols/03c_phase_aware_execution.md:219,228`
- References `AgentCoordination/opencodereview/local/worktrees/` and `AgentCoordination/opencodereview/local/request_payloads/`. The `opencodereview/` directory exists but its direct children are `completed_review_requests/`, `in_progress_review_requests/`, `pending_review_requests/`, and `plan_under_review/`. No `local/` subdirectory visible.
- **Impact:** This path structure may be created dynamically by the daemon at runtime. Not a dead reference if it's daemon-managed, but the discrepancy is worth noting for future review.
- **Proposed:** Verify the daemon creates `local/` on first use. If the path structure has changed, update the protocol.

### Finding 13: No stale PROJ references in root agent docs (PASS)
- AGENTS.md, CLAUDE.md, and CODEX.md use `PROJ-XX` only as a placeholder variable, not as references to specific projects. No stale PROJ references found.
