## Problem Statement

The codebase has a well-designed custom exception hierarchy (PROJ-45) with 10 exception classes, 19 error codes, and comprehensive documentation — but adoption is only **2.4%**. The ratio of generic ValueError to custom exceptions is **6.7:1**.

### Exception Hierarchy (game/core/exceptions.py)
```
GameException (base)
├── StateException - Object state errors
│   └── FrozenStateException - Modifying frozen objects
├── ValidationException - Input validation failures
├── ResourceException - Resource loading errors
│   └── MissingResourceException - Resource not found
├── PersistenceException - Save/load failures
└── SimulationException - Combat engine errors
    ├── ComponentException - Component operation errors
    └── FormulaException - Formula evaluation errors
```

### Error Codes (game/core/error_codes.py)
- V001-V004: Validation (VALIDATION_FAILED, OUT_OF_RANGE)
- S001-S003: State (STATE_FROZEN, NOT_INITIALIZED, INVALID_STATE)
- R001-R003: Resource (RESOURCE_NOT_FOUND, INVALID_FORMAT, RESOURCE_LOAD_FAILED)
- P001-P005: Persistence (SAVE_FAILED, LOAD_FAILED, CORRUPT_DATA, VERSION_MISMATCH, IO_ERROR)
- F001-F004: Formula (FORMULA_SYNTAX_ERROR, FORMULA_UNDEFINED_VAR, EVAL_ERROR, FORMULA_GENERAL_ERROR)
- C001-C005: Component (COMPONENT_NOT_FOUND, COMPONENT_INVALID, SLOT_OCCUPIED, INCOMPATIBLE_COMPONENT)

## Review Focus Areas

### Agent 1: ValueError Migration Mapper
- Catalog EVERY ValueError raise in game/ with: file, line, function, current message, appropriate replacement exception type, appropriate error code, and whether callers catch ValueError specifically (breaking change risk)
- Group by module (core, simulation, strategy, ui, ai, engine)
- Flag any ValueError that is genuinely correct (e.g., Python protocol methods like __init__ type guards)
- Estimate effort per file (simple/medium/complex based on caller analysis)

### Agent 2: RuntimeError & Other Generic Exception Mapper
- Same analysis for RuntimeError (32 occurrences), TypeError (53 occurrences), Exception() (28 occurrences), KeyError (6 occurrences)
- Many TypeError/KeyError may be legitimately correct (data structure operations) — distinguish carefully
- Flag only those that should be semantic domain exceptions

### Agent 3: Caller Impact Analyzer
- For each file that CATCHES ValueError/RuntimeError: would migration break it?
- Identify `except ValueError` blocks that would need updating
- Identify `except (ValueError, TypeError)` combo catches
- Identify `except Exception` blocks that implicitly catch these (no change needed)
- Produce a dependency map: "if you change X.py's raises, you must update Y.py's catches"

### Agent 4: Error Code Gap Analyzer
- Current 19 error codes — are they sufficient for all the raises being migrated?
- Propose NEW error codes needed (e.g., missing UI validation codes, strategy generation codes)
- Check if existing error codes are used consistently where they exist
- Propose the complete error code table needed post-migration

### Agent 5: Exception Catch Quality Auditor
- Audit ALL 629 try/except blocks for quality:
  - Bare except (should be zero in production)
  - except Exception without re-raise (flag unless commented)
  - except without logging (silent swallowing)
  - except with wrong exception type (catching too broad or too narrow)
  - Missing exception chaining (raise X from e)
- Categorize by: "fix during migration" vs "separate cleanup"

### Agent 6: Deserialization Validation Auditor
- Find ALL from_dict/to_dict/deserialize methods
- Check which ones validate input vs assume well-formed data
- For each that raises generic exceptions on bad input: map to appropriate custom exception
- This is a high-value target since corrupt save data produces the worst user experience

### Optional Agent 7: Test Impact Analyzer
- How many tests explicitly assert ValueError/RuntimeError?
- These tests MUST be updated during migration (breaking change)
- List every test file and assertion that references generic exceptions
- Group by: "test expects ValueError from production code" (must change) vs "test validates test infrastructure" (probably leave)
