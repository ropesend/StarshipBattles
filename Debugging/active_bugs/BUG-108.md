# BUG-108: Planet generation does not check for hex collisions with secondary/additional stars

## Description
During solar system generation, planets can be placed in hexes occupied by secondary stars within the same system. The `_generate_orbital_slots()` method in `planet_gen.py` calculates orbital distances relative to the primary star, but does not validate planet positions against the `occupied_hexes` of additional stars in the system. Zone registration occurs after planet generation, so it cannot catch the conflict either.

Observed in QA session: Planet "Arcadia VI" was placed in the same hex [1141, 2104] as star "Arcadia B", which is a secondary star in the Arcadia system.

### Similar Patterns Found
**Working pattern: Storm generation** (`game/strategy/generation/storm_generator.py:136-164`):
- `_collect_occupied_hexes()` collects ALL occupied hexes from stars (`star.occupied_hexes`), planets, and existing storms BEFORE placement
- Each storm placement is validated against the comprehensive occupied set
- The occupied set is updated after each successful placement

**Working pattern: Star companion placement** (`game/strategy/data/stars.py:506-610`):
- Maintains `occupied_hexes` set during placement
- Each companion star location is checked against the set before placement
- Set is updated after each star is placed

**Broken pattern: Planet generation** (`game/strategy/data/planet_gen.py:131-171`):
- `occupied_locations` set only tracks peer planets — no star positions included
- Secondary stars' `occupied_hexes` are never consulted
- Only the primary star's radius is used for `safe_start` distance

## Hypothesis Log

### Hypothesis 1: Missing secondary star collision check in `_generate_orbital_slots()` - CONFIRMED
**Theory:** `_generate_orbital_slots()` never checks candidate planet locations against secondary stars' `occupied_hexes`, allowing planets to be placed in hexes occupied by companion stars.
**Evidence For:**
- Line 102: `primary = stars[0]` — only primary star is used
- Line 103: `safe_start = primary.radius_hexes + 2` — only primary zone excluded
- Line 159: `if loc not in occupied_locations` — set only contains previously placed planets
- Stars[1:] (secondary stars) have `occupied_hexes` property but it's never consulted
- Storm generator has a working `_collect_occupied_hexes()` that does check all stars
- QA session confirmed planet placed in same hex as secondary star
**Evidence Against:** None
**Test:** Code inspection confirms no secondary star check exists anywhere in the planet generation pipeline
**Result:** CONFIRMED — the check is entirely absent. This is a missing feature, not a regression.

## User Context

**Reproduction Steps:**
1. Start new game or generate galaxy with multi-star systems
2. Inspect binary/trinary systems on galaxy map
3. Check if any planet hex overlaps a secondary star hex

**Expected Behavior:** Planets should never be placed in hexes occupied by secondary stars or within a buffer zone around them.
**Actual Behavior:** Planets can be placed in the exact same hex as a secondary star.

**History:** Bug has existed since planet generation was implemented — never had this check.
**Consistency:** Intermittent — only occurs when a planet's random hex happens to land on a secondary star's hex. Probabilistic based on star proximity and planet count.
**Game State:** Galaxy generation (new game or galaxy test screen).
**Known Workarounds:** None.

**User decision:** Add buffer zone around secondary stars (matching primary star's `radius_hexes + 2` safe zone pattern).
