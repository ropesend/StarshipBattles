# BUG-102: Build queue ship detail panel shows wrong species theme image

## Description
The ship detail panel in the build yards displays the Federation theme ship image instead of the correct species theme (e.g., Klingon). The ship designer's detail view shows the correct image for the same ship.

The issue is in the build queue's image resolution path through `ShipThemeManager.get_portrait_image()`, which silently falls back to the "Federation" default theme when the requested theme is not found in `theme_data`. The ship designer uses a different code path (`design_report_panel.py` with direct file lookup) that correctly resolves the theme image.

## Hypothesis Log

### Hypothesis 1: ShipThemeManager silent fallback masks correct theme_id - REJECTED
**Theory:** `ship_detail_panel.py` correctly extracts `theme_id` from `ship.design_data`, but `ShipThemeManager.get_portrait_image()` silently replaces it with "Federation" because the theme name doesn't match `theme_data` keys.
**Evidence For:**
- `get_portrait_image()` at line 240-241 explicitly replaces theme_name with default_theme when not found in theme_data
**Evidence Against:**
- Theme names in `theme.json` ("Klingons") match `THEME_DEFAULTS` in `game_config.py` — names are consistent
- The display code path actually goes through `DesignReportPanel._update_portrait()` which uses **direct filesystem lookup**, not ShipThemeManager
- User confirmed only the detail panel is broken, not thumbnails — the detail panel uses DesignReportPanel
**Result:** The display code is correct. The problem is upstream — in the data.

### Hypothesis 2: Quickstart designs saved with hardcoded Federation theme_id - CONFIRMED
**Theory:** `QuickstartBuilder.copy_quickstart_designs()` copies template design files verbatim to ALL empires. The template files have `"theme_id": "Federation"` hardcoded. Non-Federation empires get designs with the wrong theme.
**Evidence For:**
- ALL saved design files across ALL empires have `"theme_id": "Federation"` — verified across 100+ save folders
- Template files in `tests/fixtures/quickstart/designs/` have `"theme_id": "Federation"`
- `copy_quickstart_designs()` (quickstart_builder.py:242-245) uses `shutil.copy2()` — a byte-for-byte copy with no modification of content
- The empire's actual `empire_theme_id` (e.g., "Klingons") is never applied to the copied design files
**Evidence Against:** None
**Test:** Check saved designs for non-Federation empires — ALL show `"theme_id": "Federation"`
**Result:** CONFIRMED. The root cause is in `copy_quickstart_designs()` not updating `theme_id` in copied design files.
