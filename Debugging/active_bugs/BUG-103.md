# BUG-103: Build queue "Remove Selected" and drag-out removal don't work for facility queues

## Description
Items cannot be removed from facility build queues (e.g., shipyard queues on planets). Neither the "Remove Selected" button nor drag-out removal works. The items appear to disappear from the UI momentarily but reappear on refresh because they were never actually removed from the underlying data.

The root cause is that `RemoveFromConstructionQueueCommand` is missing the `queue_id` parameter that `AddToConstructionQueueCommand` already has. When the command handler processes a removal, it resolves the entity to the planet and attempts to remove from `planet.construction_queue` (the base queue) instead of the facility queue where the item actually lives.

### Key Code Locations
- `game/strategy/engine/commands.py` — `RemoveFromConstructionQueueCommand` missing `queue_id` parameter (compare with `AddToConstructionQueueCommand` which has it)
- `game/strategy/engine/command_handlers.py` — `RemoveFromConstructionQueueCommandHandler._resolve_build_entity()` does not resolve facility queues (compare with `AddToConstructionQueueCommandHandler._resolve_queue()` which does)
- `game/ui/screens/build_queue_screen.py` — `_dispatch_remove_from_queue_command()` does not pass `queue_id` (compare with `_dispatch_add_to_queue_command()` which does)

## Investigation Report

### Code Path Trace
```
UI: button/drag handler → _dispatch_remove_from_queue_command(item_index)
  → RemoveFromConstructionQueueCommand(entity_id, entity_type, item_index)  [NO queue_id]
    → CommandHandlerRegistry.dispatch()
      → RemoveFromConstructionQueueCommandHandler.execute()
        → _resolve_build_entity(entity_id, entity_type) → Planet
        → queue = entity.construction_queue  [HARDCODED to base queue]
        → queue.pop(item_index)  [Wrong queue!]
```

Compare with working ADD path:
```
UI: _dispatch_add_to_queue_command(..., queue_id=source.queue_id)
  → AddToConstructionQueueCommand(entity_id, entity_type, ..., queue_id)
    → AddToConstructionQueueCommandHandler.execute()
      → _resolve_build_entity(entity_id, entity_type) → Planet
      → _resolve_queue(entity, cmd.queue_id)  [Finds facility queue by instance_id]
      → queue.append(item)  [Correct queue!]
```

## User Context

**Consistency:** Always fails for facility queues. Works correctly for base planet queue and fleet queues.

## Hypothesis Log

### Hypothesis 1: Missing queue_id on Remove/Reorder commands — CONFIRMED
**Theory:** `RemoveFromConstructionQueueCommand` and `ReorderConstructionQueueCommand` lack the `queue_id` parameter, so their handlers always target `entity.construction_queue` (the base queue) instead of the facility queue. When the item_index doesn't exist in the base queue, the validation error is silently swallowed and nothing happens.
**Evidence For:** All 4 investigation agents confirmed identical findings. Add command has queue_id and works. Remove/Reorder commands lack queue_id and fail for facility queues. Git history shows the oversight in PROJ-208 Phase 2 (commit b15b5665).
**Evidence Against:** None.
**Test:** Fix both commands with queue_id, write facility queue tests, verify removal works.
**Result:** CONFIRMED — proceeding with TDD fix.
