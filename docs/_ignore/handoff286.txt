## Watchouts (from PROJ-284/285 cross-project + this session's planning)

1. **`last_food_ratio` becomes a `@property`** — no setter. Tests that did `cfg.last_food_ratio = X` break with `AttributeError`. Migration: replace with `cfg.last_consumption_ratios = {"organics": X}`. The MIN aggregation makes this semantically equivalent for single-resource tests.

2. **Zero-pop / zero-allocation edge case** — PROJ-284 writes `last_food_ratio = 1.0` explicitly. Multi-resource version must write `{res_id: 1.0 for res_id in economy.population_consumption}` so the min still aggregates to 1.0. Easy to miss; pin with a test.

3. **`population_food_resource` shim property** — keep it on `EconomyConfig` as a read-only property returning `self.primary_resource`. Deletes PROJ-289 will migrate callers (FoodAllocationEditor title) to `primary_resource`. Without the shim, the existing UI breaks immediately.

4. **Resource-not-in-stockpile → starvation** — a colony that has never harvested radioactives gets `stockpile.get("radioactives", 0.0) == 0`, ratio=0, min=0, species starves. This is correct gameplay but may surprise players. Don't add a grace period; document in `docs/systems/strategy_layer.md §8` in Phase 5.

5. **Don't rename `OrganicsConsumptionEngine`** to `PopulationUpkeepEngine`. The name is misleading post-multi-resource, but renames ripple into `IOrganicsConsumptionEngine` + `TurnEngineConfig.organics_consumption_engine` + tests + docs. Combining rename with behavior change obscures the behavioral change in git history. Add a docstring note about the misnomer; defer the rename.

6. **PROJ-287 is parallel-safe** — no file conflicts. If you pick up PROJ-286 in one session and another agent picks up PROJ-287, both can proceed independently. PROJ-288 consumes both and blocks until each is complete.

7. **Pre-existing sharded-runner flakes** — `test_copy_designs_without_themes_preserves_original` (theme_id pollution) persists; occasional `test_make_minimal_spec.py` pygame-font flakes. Both pass in isolation. NOT PROJ-286 regressions — same list called out across every PROJ-28X session.

8. **Context budget** — PROJ-286 is 5 phases ≈ 50-80k token work. If `check_context.py` shows you approaching 80% before Phase 5, stop at a phase boundary; split Phase 5 if needed.
