## Uncertain findings (1) — POST-CONSULT UPDATE

### LEG-02-001 — Pattern #30 slot cleanup in `_handle_window_close` — **PROJ-421 CANCELLED**

**Question raised by third-pass verifier:** The audit claimed 8 of 14 slots
were "non-modal" and not covered by Pattern #31. Verifier confirmed all 9
slot windows ARE `StrategyModalWindow` subclasses — the "8 non-modal" claim
was fabricated. The audit's internal verifier already flagged this as
"PARTIALLY ACCURATE — FATAL ANALYSIS ERROR" before publishing.

The third-pass verifier reframed the finding as "remove redundant slot-nulls"
with the supporting claim that "no caller code reads the slots for None."
The user opted to include it under that reframing.

**Post-creation codex consult invalidated the reframing.** Independent grep
found 6+ production callers that read the slot fields as
"is-this-window-open?" sentinels:

- `strategy_event_router.py:103-104` — `if wm.fleet_orders_window:`
- `strategy_screen_selection.py:52-53` — `if wm.transfer_dialog:`
- `strategy_screen_order_editing.py:73-74` — `if wm.fleet_orders_window:`
- `strategy_input_handler.py:70-71` — `if wm.planet_list_window is not None:`
- `strategy_window_manager.py:231-259` — `iter_snapshot_windows()` slot scan
- 7+ registrar controllers reading named slots for kill-before-reopen

Compound problem: `pygame_gui.UIWindow` has no `__bool__` / `__len__`, so
killed windows remain truthy. Pattern #31 auto-deregistration removes the
window from `_modals` but does **not** null the named slot fields. Removing
slot-nulls would cause method calls on dead windows in production.

PROJ-421 was cancelled with a full cancellation report at
`Projects/archived_projects/PROJ-421/findings/cancellation_report.md`.

**Recommended detector refinements (updated):**

1. When the wrapper-delegate / superseded-pattern detector counts "covered vs
   non-covered" call sites, re-derive coverage by directly grepping class
   hierarchies (`grep -rn 'class \w*Window(.*StrategyModalWindow)' game/`),
   not by string-matching slot field names against a hard-coded list.
2. **NEW — sentinel-cleanup detection.** When a slot-null cleanup is flagged
   as "redundant with deregistration," verify the deregistration actually
   nulls the slot. Class-list registration (e.g. `unregister_modal` removing
   from `_modals` list) does NOT null named instance attributes. If the
   detector cannot prove slot-null parity, classify as `intentional cleanup`
   not `redundant pattern`.
3. **NEW — truthy-after-kill check.** When a finding hinges on "no caller
   reads X for None / for truthy", look for `if X:`, `if not X`,
   `if X is None`, `if X is not None`, AND `X.<method>(` patterns where `X`
   is the candidate field. The current "redundant slot-null" detector
   assumes Python truthiness aligns with "is alive" — for pygame_gui
   UIWindow, it does not.
4. The internal verifier's catch was load-bearing here — keep that step,
   but extend it to flag **second-framing** findings (where the verifier
   rewrote the original claim) as "verifier-deferred" rather than promoting
   them back to verified. Two consecutive failed framings is a strong signal
   the observation isn't actually legacy.
5. Consider auto-downgrading a finding from CRITICAL/MAJOR to MAJOR/MINOR
   when the internal verifier marks classification as inaccurate; today
   this audit downgraded LEG-02-001 informally but the MAJOR severity
   persisted.

User decision: cancelled PROJ-421 entirely. LEG-02-001 is no longer in any
project. Two narrower follow-up projects are possible (rescope to 2 slots
with redundant nulling, or expose `is_window_active()` predicates) but
neither was opened in this run.

## INFO findings excluded by the user (7 of 7 — 100% exclusion rate)

All seven INFO items were already classified by the original shard reviewers
as "Phase-1 scanner false positive — confirmed not legacy." The bridge skill
treats INFO as opt-in and the user opted out of all of them, suggesting the
INFO bucket is over-eager:

| ID         | Why it was flagged                                            | Why it was excluded                                                  |
|------------|---------------------------------------------------------------|----------------------------------------------------------------------|
| MIN-03-007 | `__init__.py` import with `as _alias` is "shim-like"          | Documented Pattern #4 (Registry) provider-registration side-effect   |
| LEG-01-002 | Comment matched `# Old` substring                             | Line reads `# Old value (strikethrough)` — UI rendering label        |
| LEG-01-004 | Function delegates to another                                 | Documented test-patch surface (Pattern #5), 11 callsites by design   |
| LEG-01-005 | Function is a thin lookup wrapper                             | Canonical public-accessor-over-private-index pattern                 |
| LEG-01-006 | `ModifierManager` / `ModifierService` share `__init__`        | Trivial method overlap; classes serve different layers               |
| MIN-03-003 | `create_modifier` is a thin factory                           | Idiomatic factory method on definition class                         |
| MIN-004    | `to_dict`/`from_dict`/etc. delegate                           | Documented Pattern #5 Facade/Delegate                                |

**Recommended detector refinement:**

1. **Pattern #4 (Registry) side-effect imports** — exclude when `as _alias`
   in `__init__.py` AND the aliased module name appears in adjacent `noqa:
   F401` blocks of the same form. This pattern is repeated across multiple
   image providers, ability_sources, etc.
2. **Substring match on `# Old`** — restrict the deprecation-comment detector
   to require either a standalone token (`# OLD:`, `# Old:`, `# DEPRECATED`,
   `# LEGACY:`) or co-occurrence with another deprecation signal on the same
   line. The "Old value (strikethrough)" miss is a recurring failure mode.
3. **Wrapper detector** — if the wrapper's docstring contains either
   "test patch" or "test-patch surface" or "patching seam", suppress the
   finding. The Pattern #5 docstring convention is already established.
4. **`manager_service_overlap` heuristic** — require shared methods beyond
   `__init__` (the universal method). The shared-method count of 1 with only
   `__init__` should never trigger a finding.
5. **Factory-method-on-definition-class** — when the wrapper lives in the same
   file as the class it instantiates (sibling), treat it as a factory and
   suppress. The `create_modifier` / `Modifier` co-location is the canonical
   case.

## Caller-count accuracy (POST-CONSULT FINDING)

The follow-up codex consult on each surviving project found **6 of 8 projects
had wrong caller counts** in the third-pass verification report. The bias is
consistent: always undercount, never overcount. Concrete cases:

| Finding   | Verifier said | Codex consult re-grep    | Miss vector                                   |
|-----------|--------------:|--------------------------|-----------------------------------------------|
| LEG-02-002 |          10  | ~20                      | line-oriented grep missed multiline imports   |
| MAJ-001   |           19 | 22 imports / 18 files    | imports vs files double-count, missed `tests/` |
| LEG-02-003 |          61  | 61 files / 64 imports    | per-symbol breakdown imprecise                |
| MIN-002   |  26 + 4 patch| zero verified game/app.py | stale shim docstring reference uncorroborated |
| MIN-003   |            2 | 1 production + 1 test    | one of the cited callers had only a comment   |
| LEG-02-004 |            3 | 4 (`setup_screen.py` missed) | dead-code block missed in audit normalization |

Recommended detector refinement: the verifier's caller-count step must use
a **multi-pass scan**: (1) plain `from X import Y`, (2) parenthesized
multi-line imports, (3) `from X import *`, (4) TYPE_CHECKING-guarded blocks,
(5) `mock.patch('X.Y', ...)` strings, (6) `sys.modules['X']` injection. The
current single-grep approach systematically undercounts.

In none of these cases was the audit's directional claim wrong — the shim or
wrapper or alias still existed and was still legacy. But the per-finding
caller counts the audit reports were systematically off, which makes phase
planning unreliable. Fixing the verifier's grep methodology is a higher-value
refinement than tightening INFO classification.
