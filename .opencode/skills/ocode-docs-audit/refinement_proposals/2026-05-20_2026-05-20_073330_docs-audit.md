## Cross-finding inconsistency within the audit (worth a guardrail)

The audit's own outputs disagreed on the canonical filename for ability metadata: `docs_accuracy_code.md` (Tier-1 fix #4) says replace `effect_ability_metadata.py` with `ability_metadata.py` (correct), while `docs_consistency_cross.md` #8 says use `effect_ability_metadata.py` as the exact filename (wrong). **Recommend:** add a reconciliation step in report compilation that flags when the consistency reviewer and the accuracy validator name different canonical paths for the same symbol.

## Audit-missed / mis-scoped issues surfaced during verification

- **`satellites.md` internal contradiction (cross-doc #5):** The audit framed this as a single "fleet namespace" wording error at line 20. Verification found the *same doc* already describes `SatelliteConstellation` correctly as a `DeployedGroup` at line 42 — so it is an internal self-contradiction, not just drift. The finding is still VERIFIED, but the audit understated it; intra-doc contradiction detection (same term, two definitions in one file) would have caught the stronger signal.
- **"66/67 docs missing Last verified" headline is partly a scanner artifact.** G2's reviewer notes all 12 systems docs *do* carry bold-format `> **Last verified:**` lines that the deterministic scanner could not parse (only plain `Last verified:` is detected). The headline metric in `report.md` §5 overcounts. **Recommend:** make the staleness scanner recognize the bold blockquote format `> **Last verified:** YYYY-MM-DD`.
