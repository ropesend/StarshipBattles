## Audit claims worth refining (corrections, not rejections)

1. **`_default_profiler` mislabeled "removable bridge / dead code."** The cross-shard report (`state_divergence_cross_shard.md:116-126`) and remediation item #9 imply `set_default_profiler` is dead weight removable once `get_default_profiler` usage hits zero. That is true for the *getter*, but `set_default_profiler()` is still called in `ApplicationContext.create_production()` (`game/context.py:165-176`) and `profile_action` / `profile_block` (`game/core/profiling.py:116-149`) depend on `_default_profiler` as their live module-level hook. Removing the bridge is therefore a *design change*, not a dead-code deletion. **Refinement suggestion:** when the audit flags a `set_default_*` as a "removable bridge," it should also check whether the *module-level variable it sets* is read by anything other than `get_default_*` (e.g. decorators / convenience functions in the same module) before recommending removal.

2. **`ST-02-003` density_map flagged under "Random State Hygiene" but is Pattern #18-compliant.** The finding (`state_review_02.md:49-57`) is itself accurate (unseeded instance RNG + misleading docstring), but it sits in the random-hygiene section where it can be mistaken for a `random.seed()`-class state bug. It is an instance `random.Random()` (compliant) with only a docstring-accuracy defect; the guard test `tests/unit/quality/test_no_unseeded_random.py:32-37` deliberately excludes strategy generation. **Refinement suggestion:** the audit could separate "global RNG pollution" (a state finding) from "docstring drift on a compliant instance RNG" (a doc finding) so downstream bundling does not have to re-triage it.
