## Rejected findings (potential audit blind spots)

### 1. Pattern #3 — keyword-only signature wording
**Audit claim:** Doc spec for `Ship(..., *, registries: GameRegistries)` is slightly off.
**Reality:** `game/simulation/entities/ship.py:53-55` actually uses `*, registries: GameRegistries` (keyword-only). Doc and code match.
**Refinement:** The pattern_docs_validator agent prompt should explicitly require *quoting both the doc spec text AND the actual code signature side-by-side* before declaring drift. This is the single highest-value refinement here — the same agent might still make this kind of misread on similar minor-wording items.

### 2. PAT-01-UNDOC-001 — Two-Stage UIWindow Construction
**Audit claim:** Pattern is undocumented for production usage.
**Reality:** `docs/02_PATTERNS.md` Pattern #33 §"Two-stage UIWindow shape" already covers the production usage shape (lines 620-646).
**Refinement:** The undocumented-pattern reviewer should grep the pattern doc for the proposed pattern's *implementation shape phrases* (e.g. `bypass_init`, "two-stage") before declaring it undocumented. Currently the agent appears to scan only by pattern *name*, missing existing coverage that lives under a different heading.

### 3. PAT-01-PROTO-001 / PAT-01-PROTO-002 — intra-layer isinstance checks
**Audit claim:** `isinstance(ab, WeaponAbility)` and `isinstance(boundary, UnboundedRegion)` violate Pattern #2.
**Reality:** Both are intra-simulation uses against internal class hierarchies sharing a common ABC. Pattern #2 explicitly targets *cross-layer* protocol bypass — these are out of scope.
**Refinement:** The Pattern #2 reviewer rule should pre-filter by the layer of the cited file *and* the layer of the imported concrete type. Same-layer isinstance against an internal ABC chain should be auto-rejected at scan time rather than flagged as MINOR.

### 4. VER-001 / PAT-02-001 — `GameSession.get_default_registry_provider()`
**Audit claim:** Strategy-layer `GameSession` violates Pattern #3.
**Reality:** Pattern #3's prohibition is *simulation-scoped* (the doc text says so explicitly at lines 12, 98, 104). Audit's own internal verifier already disputed this.
**Refinement:** The Pattern #3 scan rule should restrict its `from_layer` filter to `simulation` only. The current scan emits strategy-layer matches as CRITICAL when they are at most stylistic preferences.

### 5. PAT-01-CFG-002, PAT-01-CFG-003, PAT-01-CFG-004, PAT-01-MODAL-001, MIN-01
**Audit pattern:** Several MINOR findings carry self-recommendations of "no action needed" or "documented as intentional" in the same row.
**Refinement:** The shard reviewers should drop these from the candidate list rather than emit a finding the same paragraph then closes. If a finding has its own "no action" justification, it shouldn't reach the executive summary as a counted MINOR — it inflates the headline count without producing actionable work.
