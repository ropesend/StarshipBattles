| 2026-04-28 | Architecture: Option A (StrategyModalWindow base class), not Option B (helper functions) or Option C (pygame_gui native modal flag) | Only Option A makes the contract structurally unforgettable. Option B keeps slots and still requires per-window discipline. Option C is unproven against the strategy event router's pan/zoom integration. |

Each commit keeps exactly one track active per window. |
| 2026-04-28 | `settings_window` stays as direct non-modal slot field; no `non_modal=True` flag on the base class | A flag would invert the "subclassing == modal contract" rule and re-introduce manual-discipline failure mode. If a second non-modal window appears later, extract `StrategyNonModalWindow` peer class then. Don't pre-generalise. |
| 2026-04-28 | `move_choice_window` (currently inline `pygame_gui.UIWindow`) is promoted to `MoveChoiceWindow(StrategyModalWindow)` named subclass | Adapter wrapping inline construction would re-introduce a per-window special case. Promotion is ~10 LOC and brings move-choice fully under the structural contract. The button callbacks already use `kill()` for cleanup; the new base class subsumes the lifecycle automatically. User-confirmed. |
| 2026-04-28 | All 5 currently-untracked editor windows (Food / Atmosphere / Gravity / Water / RadiationShield) included in PROJ-313 (Phase 7) rather than split to a follow-up bug | Closes the click-through bug class structurally in one project. ~30% scope increase but eliminates the bugs at the architecture layer rather than leaving 5 latent click-throughs. User-confirmed. |
| 2026-04-28 | `_handle_window_close` event listener deleted entirely in Phase 8, not kept as belt-and-suspenders | Belt-and-suspenders here is a Rule 3 violation. The event listener would silently absorb bugs in any future `StrategyModalWindow` subclass that forgot to call `super().__init__`. The structural contract should be the only path. |
| 2026-04-28 | `_pending_confirmation_dialog` asymmetry (present in `_is_blocking_ui_element_at` but absent from `has_modal_open`) is out of scope | It's a `UIConfirmationDialog` (pygame_gui stock), not a managed slot. Different lifecycle. File a separate small ticket. User-confirmed. |
| 2026-04-28 | Test contract replacement: `__init_subclass__` registry + parametrised behavioural test, not `__subclasses__()` | `__subclasses__()` is order-dependent and only finds loaded classes; depends on test module import order. `__init_subclass__` runs on class definition and is reliable. |
| 2026-04-28 | Static guard test added: greps `game/ui/screens/strategy_windows/` and modal-relevant `game/ui/screens/*.py` for direct `pygame_gui.UIWindow` subclasses; asserts each is `StrategyModalWindow` or in an explicit non-modal allowlist (currently just `SettingsWindow`) | Catches the "new dev forgot to subclass" case at CI time. Cheaper than runtime detection. |
| 2026-04-28 | `iter_live_modals()` does the GC walk (`[w for w in self._modals if w.alive()]`) on every call, not lazily | Defensive against parent-kill cascade orphans. Cheap (modal lists are short — at most ~5 active at any time). Unit test pins the invariant. |
| 2026-04-28 | `iter_live_modals()` yields insertion order, not z-order | Documented as a constraint. Both `has_modal_open` (any-True) and `_is_blocking_ui_element_at` (any-hit) are correct under insertion order. Future "topmost wins" features must add z-order awareness explicitly. |
| 2026-04-28 | Phase ordering: 1 (foundation) → 2 (router OR-bridge) → 3 (event-listener-only — riskiest cleanup style first) → 4 (dual-cleanup) → 5 (registrar-callback-only) → 6 (move_choice promotion) → 7 (untracked editors — behaviour-change phase) → 8 (demolition + docs) | Tackles the riskiest windows first while the OR-bridge protects the test suite. Phase 7's behaviour change (newly-blocking modal during editor open) is isolated for an audit pass before propagation. Phase 8 is purely subtractive. |
