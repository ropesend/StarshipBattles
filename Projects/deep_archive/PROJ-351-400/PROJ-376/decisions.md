| 2026-05-07 | **Do NOT migrate `BuildQueueScreen` to PROJ-313's `StrategyModalWindow` base class.** | (a) `BuildQueueScreen` is not a `UIWindow`; it is a plain object owning a full-screen `UIPanel` tree. | 2026-05-07 | **`is_visible()` is the right gate for input + draw routing; the modal-block check at `strategy_event_router.py:58` keeps `is not None`.** | Today's three `is not None` checks at event-router :58, input-handler :55, and screen :246 conflate "instance exists" with "currently displayed". (b) Screen draw must NOT draw a hidden screen → migrate to `is_visible()`. (c) Modal-block check at the event router gates whether galaxy-map clicks fire — when the build queue is hidden, the galaxy IS visible (`ui.show_ui()` ran in `_on_build_queue_close`), so the original semantics of "is the build queue currently the focused overlay" are preserved by `is_visible()`. **All three sites migrate to `is_visible()`.** |
| 2026-05-07 | **`open_for_yard(yard, *, hex_coord, portrait_surface)` accepts `hex_coord` as keyword arg, not recomputed.** | The existing 3 manager call sites compute `hex_coord` differently: planet does `parent_sys.global_location + planet.location` (line 96); fleet uses `fleet.location` directly (line 253); `on_navigate_to_hex_build` accepts `hex_coord` as an arg already. The manager's new `_open_build_queue(yard, hex_coord, portrait_surface)` helper consolidates the call sites. |
