## Audit Remediation (2026-05-05)

The OpenCode review of PROJ-360 (`Reviews/results/2026-05-05_073251_code_proj-360-review-shipstatscalculator-domain-decompo_*`) reported 2 CRIT + 11 MAJ findings against the new registry / domain-decomposition. This pass remediates the prioritized set. Sharded suite: 17777 passed / 0 failed / 4 skipped (+7 net tests over the prior 17770 baseline).

| Finding | Severity | Verdict | Rationale |
|---------|----------|---------|-----------|
| EXT-01 | CRIT | **Fixed** | Per-ability dedup. `STAT_CONTRIBUTOR_REGISTRY` is now a dict keyed by ability name; `register_stat_contributor` raises if the ability is already registered, regardless of `domain` tag. The `domain` field is now an opt-in diagnostic label only. The previous `test_same_ability_different_domain_is_allowed` test, which codified the buggy behavior, was deleted. |
| EXT-12 | CRIT | **Fixed** | Registered contributors now receive `(ship, comp, acc)` and participate in the same accumulate-then-commit pattern as the built-ins. `apply_registered_contributors` passes the calculator's `acc` dict; `_phase_stats_aggregation` was updated to forward it. |
| EXT-02 | MAJ | **Fixed** | `BUILTIN_HANDLED_ABILITIES` frozenset enumerates the 9 abilities the built-in domain handlers process. Each built-in handler (`movement.aggregate_propulsion`, `defense.aggregate_defense`, `command.track_multiplex`, `launch.aggregate_hangar`) consults `is_builtin_suppressed_for(ability)` before its inner block. When a contributor is registered for a built-in ability, the built-in is skipped — a single execution per component, no double-counting. |
| EXT-05 | MAJ | **Fixed** | Shield energy-cost extraction in `defense.aggregate_defense` now iterates `comp.get_abilities("ResourceConsumption")` filtered on `resource_type == "energy"` instead of scanning the entire `comp.ability_instances` list. ### Critical regression test added

`test_registering_shield_projection_does_not_double_count` (`tests/unit/simulation/entities/test_stat_contributor_extension.py`) registers a contributor that adds `7 × capacity` to `acc['max_shields']` for every ShieldProjection-bearing component, recalculates a battleship, and asserts `max_shields == 7 × baseline_max_shields`. Without the EXT-02 fix the value would be `8 × baseline` (built-in 1x + registered 7x). The test pins both halves: hook fires AND built-in is suppressed.

`test_registered_contributor_receives_acc_dict` pins the EXT-12 fix: the contributor receives a real `dict` containing built-in keys (`thrust`, `max_shields`).

`TestBuiltinSuppression` in `test_registry.py` (4 tests) pins the new `is_builtin_suppressed_for` API at unit scope.
