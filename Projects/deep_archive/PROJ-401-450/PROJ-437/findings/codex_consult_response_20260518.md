## Risks

- The shipped code now makes item rows visible in fleet-backed container snapshots, but fleet-to-fleet item execution still appears to route through the generic cargo branch rather than a pod/vehicle-aware path (`game/strategy/engine/order_handlers/transfer.py:206-209`, `game/strategy/engine/order_handlers/transfer_branches.py:458-486`). If users can stage those rows between two fleets, backend behavior may diverge from the new UI surface.
- The current implementation did not realize the original design aspiration of per-facility planet containers or per-container acceptance validation in the dialog. That is fine for PROJ-437 as shipped, but it means future work should not assume those contracts already exist (`game/strategy/facade/slices/planet_slice.py:95-115`; `Projects/active_projects/PROJ-437/design.md:35-37`, `72-76`).
- The mass preview is intentionally target-centric for explicit over-capacity styling. Source remaining can go negative without its own flag, so any future chrome that needs symmetric source warning will need an additional field (`game/ui/screens/transfer_mass_preview.py:44-60`, `106-115`).
