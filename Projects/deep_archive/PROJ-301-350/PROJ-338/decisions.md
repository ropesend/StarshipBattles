# PROJ-338 — Decisions Log

| ID | Decision | Rationale |
|---|---|---|
| D-001 | Test the drag handler via synthesized pygame events (not pygame_gui live). | The handler accepts `pygame.event.Event` directly and calls `.collidepoint`, `.get_abs_rect`, `.handle_click`. Construct events with `pygame.event.Event(MOUSEBUTTONDOWN, button=1, pos=(x,y))` and stub `items_scrollable`/`virtual_table`/`build_queue_panel`/`construction_queue` with MagicMocks shaped to the production contract. |
| D-002 | Use the `__new__` bypass + builder-stub pattern for panels with facade-coupled `__init__` (`PlanetReportPanel`, `SystemTreePanel`). | These panels currently load resource icons via filesystem, build pygame_gui widgets, and read `scene.session.active_empire` chains in `__init__`. PROJ-329 work is separate; per project constraints we accept the bypass pattern and characterise current behavior on instances built with `object.__new__(Panel)` followed by manual attribute injection. |
| D-003 | `BuildQueueController` test file is **extended in place**, not rewritten. | The existing `tests/unit/ui/panels/test_build_queue_controller.py` (1108 LOC) carries the PROJ-69/79/208 callback semantics — replacing it would lose proven coverage. Add a new top-level `class TestCharacterizationCoverageGaps:` for the missing slices (`load_designs_by_category` filtering, role filter reset, `_validate_designs` failure path, `_calculate_build_turns` formula corner cases, `refresh_design_report` paths). |
| D-004 | `BattlePanel` tests use the mocked-pygame substitution pattern that the existing `test_battle_panels.py` already establishes. | Switching to live pygame would invalidate the existing 975 LOC of tests. Add a parallel `test_battle_panels_characterization.py` that uses the same `MockRect` + `patch.dict(sys.modules, {'pygame': mock_pygame})` setup but pins behaviors not covered today (banner rect recording per draw frame, scroll-offset interplay with click, `_get_ships()` fallback when ui_service returns non-list, derelict + dead status rendering branches, control-panel battle-over text selection). |
| D-005 | `SystemTreePanel` characterization tests live in `tests/unit/ui/panels/test_system_tree_panel_characterization.py`, separate from the existing smoke + hazard tests. | Avoids touching the audit-S1.3 smoke tests (which are integration-tier and must stay green byte-identical). Characterization file uses a stubbed `scene_interface` and asserts on `self.items` / `self.root_items` shape after `set_items` for the various grouping paths (single planet, planet stack, hex grouping, flat_view, system_obj+effects). |
| D-006 | `_format_star_hazard_hints` already has dedicated coverage — extend, do not duplicate. | The existing `test_system_tree_panel_hazard.py` covers the happy paths. Add corner-case rows there (multiple star providers, `ThrustModifier` <1 and =1, missing `ability_data` keys, non-star providers ignored). |
| D-007 | `PlanetReportPanel` characterization additions go to a new file `test_planet_report_panel_characterization.py` rather than further bloating the existing 981 LOC test file. | Existing file is structured around the pure helpers; characterization file pins the panel-object behavior (`__init__` with/without complexes, `update_planet` rebinds view but conditionally rebinds empire/race_registry per PROJ-292, `kill`, `_update_complexes_list` with empty/single/duplicate facilities, resource icon fallback when file missing, Net cell colour-tint application). |
| D-008 | Drag handler tests are split per state-machine transition, not per public method. | Drag handler bugs are state-machine bugs. Tests are organised by transition: `test_design_drag_start`, `test_queue_item_pending_then_drag`, `test_drop_inside_queue_panel_inserts_at_index`, `test_drop_outside_panel_drops_item`, `test_click_without_drag_selects_item`, `test_multi_select_disables_all_drag_paths`, `test_callback_vs_legacy_pop_path`, etc. Each test asserts on observable state (`is_dragging`, `dragged_item`, `selected_design`, callback invocations, queue mutation). |
| D-009 | Per-file commits. | Same discipline as PROJ-329A D-007. Each new test file lands in its own commit so bisect/revert is per-class. Drag handler lands first (highest risk). |
| D-010 | "Don't fix bugs" — characterise weird behavior and note it. | If a test surfaces e.g. `_pending_queue_index` not cleared on multi_select toggle mid-pending, write the test to assert current behavior and add an "Observation" entry below. The bug fix is a separate ticket. |
