!EXECUTE_PROTOCOL: Projects\protocols\07_extract_phase.md

Extract a phase from an existing project into its own independent multi-phase project.

## When to Use This Prompt

Use this when:
1. A phase has grown too complex for single-phase handling
2. A phase requires fundamentally different expertise or timeline
3. Parallel development would benefit the overall project
4. Agent judgment determines the phase scope exceeds expectations

## Extraction Workflow

### Step 1: Identify the Phase

Specify the project and phase to extract:

```
Source Project: PROJ-XX
Phase to Extract: N
Reason: [Why this phase needs its own project]
```

### Step 2: Preview the Extraction

Run the extraction script in dry-run mode to preview changes:

```bash
python Projects/scripts/extract_phase.py PROJ-XX N --dry-run
```

Review the preview output:
- New project ID that will be created
- Files that will be modified
- Confirm the extraction is appropriate

### Step 3: Execute Extraction

If the preview looks correct, run the actual extraction:

```bash
python Projects/scripts/extract_phase.py PROJ-XX N
```

Optional flags:
- `--title "Custom Title"` - Provide a custom title for the new project
- `--reason "Detailed reason"` - Document the extraction reason

### Step 4: Start Planning the New Project

After extraction:
1. The script outputs the new project ID (e.g., PROJ-42)
2. Run the **Start Project** prompt on the new project
3. The extraction context in `findings/extraction_context.md` provides background
4. Plan the new project fresh - not constrained by original phase structure

### Step 5: Verify Original Project

Confirm the original project was updated correctly:
1. Check `plan.md` Quick Status table shows "Extracted -> PROJ-XX"
2. Check the phase checklist shows "Status: Extracted"
3. Check `decisions.md` has the extraction entry

## What Happens to the Original Phase

- The phase status becomes "Extracted"
- The phase checklist preserves original tasks as "Archived for Reference"
- The phase will auto-complete when the sub-project is archived
- This is detected during the Audit protocol (Protocol 04)

## Agent-Initiated Extraction

If an agent determines during implementation that a phase is too complex:

1. Document the observation in Current State
2. Ask user: "Phase N has grown complex. Recommend extraction. Proceed?"
3. If approved, run extraction workflow above
4. If declined, continue but note the decision in decisions.md

## Example Usage

### Manual Extraction
```
User: I want to extract Phase 3 from PROJ-40 because it's become a major subsystem

Agent:
1. python Projects/scripts/extract_phase.py PROJ-40 3 --dry-run
2. [Review output]
3. python Projects/scripts/extract_phase.py PROJ-40 3 --reason "Phase evolved into major authentication subsystem"
4. Now run Start Project prompt on the new project
```

### Agent-Recommended Extraction
```
Agent: While implementing Phase 5, I've identified it requires:
- 15 tasks with 60+ subtasks
- Multiple architectural decisions
- Independent testing infrastructure

I recommend extracting this phase. Shall I proceed?

User: Yes

Agent: [Runs extraction workflow]
```
