Class-based panel renderers would force a `RendererHandles` dataclass right now; that belongs to Phase 8 when the screen is slimmed. Panel-builder functions verify the "per-panel modules own panel construction" invariant without pre-committing a handle-storage refactor. |

| 2026-04-18 | Phase 6 Controller: `on_change` callback + `scene_callback` | Controller takes `on_change: Optional[Callable[[], None]]` in its constructor and fires it after every mutation. The screen passes `self._rebuild_ui` at construction time — this is how the pygame_gui tree refreshes without the controller importing pygame. Separately, `scene_callback` is passed through to `start_battle` (fires `"start_battle"` / `"start_headless"`) and `return_to_menu` (fires `"return_to_menu"`). Keeps the controller pygame-free AND unit-testable with pure mocks. |
| 2026-04-18 | Phase 6 property shims on screen for end-condition settings + `_get_toggle` | `tick_limit`, `end_all_destroyed`, `end_all_derelict`, `end_mass_ratio`, `mass_ratio_threshold`, and `_get_toggle` gain `@property` accessors on the screen that route to `self.controller.*` / `self.controller.get_complex_toggle(...)`. | 2026-04-18 | Phase 6 latent bug fixed: end-condition settings inside `@available_designs.setter` | A Phase 3 edit accidentally left the `self.tick_limit = 100000` / `self.end_all_destroyed = True` / etc. block inside the `available_designs` property setter. The block's presence inside the setter was invisible on review because the indentation still suggested an `__init__` body. Moving the fields to the controller deletes the setter-body lines entirely — the bug can't reappear. |

| 2026-04-18 | Phase 11: add_side/remove_side tolerate bounds silently (no-op at cap) | Controller methods CATCH the state-layer's `ValueError` at MIN/MAX and return quietly rather than raising. Rationale: the UI button's disabled state is the primary bounds enforcement; the controller-level tolerance is defense-in-depth so a misfired event doesn't crash the session. Logs a warning via the module logger on add-at-max for observability. |
| 2026-04-18 | Phase 11: remove_side view-model reconciliation rules | When `remove_side(index)` executes: (a) if `active_side == index` (removed the active side), clamp `active_side` to the new last valid index; (b) if `active_side > index` (removed a side before the active one), decrement `active_side` by 1 so it tracks the same logical side after the renumbering; (c) if `active_side < index` (removed a side after active), no change needed. Also resets `active_fleet_index = 0` and clears selection. Documented in the Controller test `TestAddRemoveSide` class. |
| 2026-04-18 | Phase 11: drop "(Left)" / "(Right)" dropdown suffixes | With N>2 sides, "Left" / "Right" cosmetics lose meaning (entry vectors arrange teams around a ring — see `resolve_team_entry_vectors`). The InputHandler's side-dropdown parser uses `int(event.text.split()[-1])` with a 0-fallback on parse failure — safe against future UX polish that reintroduces cosmetic suffixes as long as the numeric index is the last token. |
