## Per-project workflow (apply to each of the 4 projects)
================================================================================

### Step 1 — Pre-project orientation

- Run `python Projects/scripts/current_task.py PROJ-XXX` to see the live current state.
- Read the plan.md "Current State" block + "Group C execution context" block in Dependencies.
- Confirm the serial gate (predecessor project is complete OR you are PROJ-452 starting the chain).
- Read the next-pending phase checklist in full.

### Step 2 — Execute each phase

For each phase from first to last:

- Open `phase_N_checklist.md`. Read in full before starting any task.
- Execute tasks in the listed order unless a task's "Notes" explicitly allows reordering.
- Use the TDD pattern the project documents:
  - **PROJ-452** — RED-then-GREEN. Each Phase has a new failing test before the fix.
  - **PROJ-455** — Characterization-first (test-only coverage project). Phase 1 establishes the fixture; Phase 2 lands the parametrized test (Task 2.1 = completion branch + Task 2.4 = in-progress branch, BOTH required per `phase_2_checklist.md`'s Phase Completion Checklist); Phase 3 updates the DI log.
  - **PROJ-458** — RED-then-GREEN per window. Each phase: new dedicated characterization tests against the bypass-init shell first (RED), then apply the two-stage retrofit (GREEN).
  - **PROJ-460** — Characterization-first refactor. Each phase has the round-trip test landing GREEN against current code (it's a structural extraction, not a behavior change); the gate is "post-extraction round-trip still GREEN".
- Run targeted pytest after each task (the checklist tells you which file).
- At the end of each phase: run `python Tools/test_sharded/test_sharded.py` (full sharded suite).
- **PROJ-460 Phase 1 and Phase 3 extra gate**: ALSO run `pytest tests/integration/replay/ tests/integration/save_load/ -v`. These are the critical regression gates for replay/serde work; do not declare the phase complete without them green.
- Mark task checkboxes `[x]` as you go.
- Update plan.md "Current State" block whenever you pause (Last Updated date; Active Phase; Last Action; Next Action; Blockers).

### Step 3 — Phase completion gate

For each phase:
- All task checkboxes in `phase_N_checklist.md` are `[x]`
- Targeted tests green
- Sharded suite green
- Replay/save-load suite green (PROJ-460 Phase 1 + Phase 3 only)
- `python Projects/scripts/validate_phase.py PROJ-XXX N` reports PASSED
- Update `phase_N_checklist.md` Status: → `Complete`
- Update `plan.md` Quick Status table row N → `Complete`
- Update `plan.md` Current State → next phase OR project-complete

### Step 5 — End-of-project codex audit (MANDATORY after every project)

After ALL phases of a project are complete (including any STOP-confirmation):

1. Dispatch a codex consult auditing the just-completed project. Use `Tools/agent_coordination/partner_invoke.py` via the standing pattern. See templates from the prior per-bucket audits:
   - Bucket B audit (covers PROJ-452 + PROJ-455 originally): `AgentCoordination/Scratchpad/Consult/20260519T014918Z_audit-bucket-B-engine-services/response.md` + its `request.md`
   - Bucket C audit (covers PROJ-458 originally): `AgentCoordination/Scratchpad/Consult/20260519T014918Z_audit-bucket-C-ui-cluster/response.md` + its `request.md`
   - Bucket D audit (covers PROJ-460 originally): `AgentCoordination/Scratchpad/Consult/20260519T014918Z_audit-bucket-D-loc-extractions/response.md` + its `request.md`

2. Audit consult brief (per project):
   - Scope: just the one project that just completed
   - allow_tests: false
   - Ask codex to verify: (a) all phase checklists actually closed correctly, (b) the production code changes match what the plan documented, (c) no behavior regressions visible in the diff, (d) no new discovered_issues that should be logged, (e) the project's verification checklist gates are all met.
   - Output: per-project response.md in a new consult leaf under `AgentCoordination/Scratchpad/Consult/<UTC-ts>_PROJ-XXX-end-of-project-audit/`.

3. Read codex's response.md.

4. **If codex flags VERIFIED issues** (test the claim — read the file/line codex cites before treating it as real):
   - For each verified issue, create a NEW PHASE in the same project addressing it.
   - Phase numbering: continue from the last phase (e.g., if Phase 5 was the original last, new audit-driven phases start at Phase 6).
   - Update the plan.md Quick Status table to add the new phases.
   - Update Current State to point at the new phase.
   - Execute the new phase using the same workflow above.
   - Repeat the codex audit if the new phases are non-trivial (>30 LOC of production change).

5. **If codex's findings are over-stated or wrong** (you verified, found the claim doesn't hold): document the false-positive in `decisions.md` with evidence and move on. Do not create a phase for it.

6. **If codex's findings are truly new but out-of-scope** (legitimate issue but outside this project's job): log via `/claude-di-log` so it lands in `AgentCoordination/discovered_issues/log.jsonl`, then move on.

7. Only after all codex-verified issues are addressed AND the new phases close green should you mark the project complete and advance to the next.
