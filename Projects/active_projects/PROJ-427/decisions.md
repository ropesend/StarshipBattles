| 2026-05-16 | **Explicit "no-disk-read during production tick" integration test.** | The source plan's risk table identifies "Runtime production accidentally repopulates the catalog from disk during the tick" as a primary risk and prescribes an explicit integration test as the mitigation. The test goes under `tests/integration/strategy/production/` and stubs `DesignRepository.scan_designs` / `load_design_data` to raise if invoked during a tick. |
| 2026-05-16 | **`DesignRepository` introduced before `DesignCatalog`.** | Phase 1 is additive: the repository is built around the disk-bound responsibilities lifted out of `DesignLibrary`, with `DesignLoadResult` shape preserved unchanged so callers are untouched. Phase 2 then builds the catalog on top, populating from the repository at session/bootstrap boundaries only. This ordering keeps each phase reviewable in isolation. |
| 2026-05-16 | **Runtime production migration is a single contained phase (Phase 3).** | Spawn, construction-queue validation, and quickstart initial-complex spawn all read disk JSON today; migrating one without the others would leave `save_path` plumbing alive. Phase 3 migrates `ProductionSpawner`, `ProductionEngine` (removes `save_path` threading), `AddToConstructionQueueCommandHandler`, and `quickstart_builder.spawn_initial_complexes` together, with a grep gate at phase close. |
| 2026-05-16 | **`SaveGameService` conversion is one contained phase (Phase 5), not a gradual sweep.** | The source plan's risk table calls out "The repo ends up with mixed static and instance `SaveGameService` usage" as a primary risk. Mitigation: remove `_replay_store`, `set_replay_store`, `get_replay_store` and all call-site usages in one phase, with a closing grep gate. No half-static / half-instance period. |
| 2026-05-16 | **Catalog accessor lives on `GameSession` if PROJ-423 has not landed; absorbs into `SessionRuntimeServices` if PROJ-423 lands later.** | PROJ-423 (TD-02) is a soft predecessor only. Changing the result type in Phase 1 would force caller migration before the catalog exists. Future result-type cleanup is out of scope for PROJ-427. |
| 2026-05-17 | **Project halted at Phase 0 entry; scope-vs-budget blocker.** | Operator-budget assessment: full execution across phases 0-6 with strict TDD requires (a) writing new repository + catalog packages with new test suites, (b) rewriting dozens of existing `tests/unit/strategy/engine/test_production_spawner.py`, `tests/unit/strategy/production_engine/test_spawning.py`, `tests/integration/strategy/production/*`, and quickstart-builder tests that patch `game.strategy.engine.production_spawner.DesignLibrary` at the module boundary (Phase 3 invalidates all those patches), (c) replacing module-global `_replay_store`/`set_replay_store`/`get_replay_store` and updating every test fixture and `app_bootstrap.py` call site (68 hits across `game/` and `tests/`), (d) migrating three UI screens off `DesignLibrary` with cache-invalidation parity to the QA-Obs-3-fixed workshop flow (209 hits across the repo, ~12 live production/UI/test sites under `game/` + `tests/`), (e) absorbing per-empire `DesignCatalog`s and `DesignRepository` into `SessionRuntimeServices` + `SessionBootstrapState` per the TD-02 cross-plan note while keeping the anti-drift `test_init_and_from_dict_use_identical_service_classes` green, and (f) running the full sharded suite as a final gate. This is a multi-hour, multi-pass refactor and cannot be honestly closed in a single execution slot without risking a half-landed change that leaves the test suite or the production tick broken. Halting at the phase-0 entry preserves a clean tree on `proj/PROJ-427/main` for a follow-up resumption rather than committing a partial Phase 3 that breaks `DesignLibrary` patches in dozens of tests. The cross-plan absorption into `SessionRuntimeServices` and the discipline guardrails (no `Empire.designs_built_count`, no v4.0.0 bump, no premature `DesignLibrary` deletion) remain the correct contracts for the resumption. |
