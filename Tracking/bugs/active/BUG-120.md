# BUG-120: Planet "Yard" resource row shows yard capacity instead of actual queue consumption

## Description
On the Planet detail view (resource summary table), the **Yard** row reports
the same magnitude across every resource (Metals / Organics / Vapors /
Radioactives / Exotics — all `-22,106.5/turn` in the captured save), even
though the planet's Build Queue contains a single item (`bs_battleship_gc`)
that consumes only Metals 30,000, Radioactives 14,185, Exotics 18,788 per
turn (and nothing in Organics or Vapors).

The two views disagree on actual per-resource consumption:

| Resource | Planet "Yard" row | Build queue per-turn | Reality |
|---|---|---|---|
| Metals | -22,106.5 | 30,000 | 30,000 (single item) |
| Organics | -22,106.5 | — (0) | 0 |
| Vapors | -22,106.5 | — (0) | 0 |
| Radioactives | -22,106.5 | 14,185 | 14,185 |
| Exotics | -22,106.5 | 18,788 | 18,788 |

## Root Cause — Two different formulas
- `_project_yard_drain()` in
  `game/strategy/services/planet_economy_projector.py:131-156` sums each
  yard's `build_rate` (the yard's maximum capacity per resource — uniform
  22,106.5 across all 5 resources at this yard's size/level). It never
  inspects what is queued.
- `get_resource_rate_text()` in
  `game/ui/screens/empire_build_queue_formatter.py:147-167` reads
  `cost_per_tick` from the first queued item and multiplies by 100
  ticks/turn. Real per-item consumption.

The Planet view is therefore showing **yard capacity**, not **actual draw**.

## Fix
Rewrite `_project_yard_drain()` so it iterates the queued items on each yard
source and sums their `cost_per_tick * 100` per resource (the same source of
truth used by the build queue panel). Result:
- Empty queue → no Yard line draws (or zero across the board).
- Queue with items → Yard row equals the per-resource sum of currently-firing
  items, matching what the Build Queue panel reports.

If both views need a "yard capacity" alongside "actual draw", split into two
rows (e.g., "Yard Capacity" vs "Yard Drain") rather than overloading one
ambiguous row.
