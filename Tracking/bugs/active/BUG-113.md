# BUG-113: Combat Lab — Projectile weapon tests show no pass/fail indicators

## Description
Tests without `validation_rules` (all projectile, seeker tracking, and damage scenarios) display empty gray circles instead of pass/fail indicators in the Test Viewer list. Beam weapon tests, which have `validation_rules` defined, show green checkmarks or red X's.

The root cause is two-fold:
1. Static validation at startup (`MetadataManagementService.validate_all_scenarios()`) skips scenarios without `validation_rules`, leaving `last_run_results` unpopulated.
2. After running a test, `registry.update_last_run_results()` is called, but the `validation_results` key required by the renderer (`_draw_validation_flag()` in `renderer.py`) is absent when no `validation_rules` exist.

The renderer falls through to an empty gray circle when `validation_results` is missing from `last_run_results`.

**Key files:**
- `game/ui/screens/test_lab/renderer.py` — `_draw_validation_flag()` (lines ~986-1032)
- `combat_lab/services/metadata_management_service.py` — static validation skip logic (lines ~52-54)
- `combat_lab/scenarios/projectile_scenarios.py` — no `validation_rules` defined

- 2026-04-12: Resolved by the Combat Lab cleanup project. `MetadataManagementService` was deleted entirely, and the `_run_static_validation` startup pass was removed from `TestLabUIController`. The `validation_rules` static-metadata field is gone — every scenario now implements `validate(engine) -> List[Check]`, and `TestScenario._run_validation()` populates `results['validation_results']` for every run. Projectile and seeker scenarios therefore produce the same renderer payload as beam scenarios after any run; the empty-indicator case only remains for tests that have never been run (expected behavior, not a bug).
