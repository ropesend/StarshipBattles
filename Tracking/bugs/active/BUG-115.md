# BUG-115: New Game Setup — Cancel button does not work

## Description
On the new-game setup flow, the Cancel button does not respond when
clicked. The button is visible and looks interactive, but pressing it
has no effect — the screen remains open and no cancel action is
performed.

Reported during QA Session 20260426_083959 at 08:43:54 while the user
was on the Race Setup screen.

### Suspected scope
Two Cancel buttons exist in the new-game flow and the report could
apply to either (or both):

- **Race Setup screen** — [race_setup_screen.py:629-634](../../../game/ui/screens/race_setup_screen.py#L629-L634)
  (`btn_cancel`), handler at [race_setup_screen.py:904-908](../../../game/ui/screens/race_setup_screen.py#L904-L908)
- **New Game Setup screen** — [new_game_setup_screen.py:191-196](../../../game/ui/screens/new_game_setup_screen.py#L191-L196)
  (`btn_cancel`), handler at [new_game_setup_screen.py:525-529](../../../game/ui/screens/new_game_setup_screen.py#L525-L529)

Both handlers call `on_cancel_callback()` then `self.kill()`, which
matches the working Cancel pattern at
[save_selection_window.py:348-352](../../../game/ui/save_selection_window.py#L348-L352).
Wiring looks correct on paper.

### Initial investigation hints
- An Explore-agent investigation suggested the most likely cause is
  in `NewGameSetupScreen.process_event()` around
  [new_game_setup_screen.py:357-358](../../../game/ui/screens/new_game_setup_screen.py#L357-L358),
  which may early-return while the race-setup modal is active and
  swallow the cancel click before the button check runs.
- No log entry was recorded at the timestamp of the click, which is
  consistent with the click event never reaching the intended handler.

### Reproduction
1. Launch the game.
2. Start a new game and proceed to the Race Setup screen.
3. Click the Cancel button.
4. **Expected:** screen closes, returns to previous screen.
5. **Actual:** nothing happens.

(Worth confirming whether the Cancel button on the parent New Game
Setup screen has the same issue.)
