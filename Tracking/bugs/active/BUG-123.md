# BUG-123: Event Log shows events from all empires combined; should filter to the active empire

## Description

In a multi-empire / hot-seat game, opening the Event Log shows events
from every empire in a single combined list. Each empire should only
see its own events.

The session screenshot shows entries for the "Chimera" system (empire 0
home system) and the "Lahore" system (empire 1 home system) interleaved
in the same table:

[![Event log mixing two empires' production-paused events](../../../tools/qa_observer/session_data/20260428_190154/images/bug_capture_190730.png)](../../../tools/qa_observer/session_data/20260428_190154/images/bug_capture_190730.png)

User commentary at QA Session 20260428_190154 [19:06:49 – 19:07:31]:
> "When one Empire has everything loaded, it needs to focus on that
> Empire and load their event log. We need separate event logs for the
> different Empires."

## Code investigation findings

The `Event` dataclass already carries the empire ownership:
[`game/strategy/events/event_log.py:26`](../../../game/strategy/events/event_log.py#L26)
defines `empire_id: int` and `to_dict()` serialises it. **The data is
there — the UI just isn't filtering on it.**

The unfiltered path:
1. `EventLogRegistrar.open_all()` calls `facade.get_all_events()` →
   `EventSlice.get_all_events()` → `EventLog.get_all_events()` and
   passes the raw global stream to the window.
2. `EventLogWindow.__init__` stores it in `self.all_events`.
3. `EventLogDataSource` filters by category (combat / production /
   colonies / fleet ops) only — never by `empire_id`.

The active empire is already tracked elsewhere:
[`game/ui/screens/strategy_screen.py:171`](../../../game/ui/screens/strategy_screen.py#L171)
`StrategyScreen.current_empire` resolves
`self.human_player_ids[self.current_player_index]` →
`self.empires[player_id]`. `StrategyGameStateManager.advance_turn()`
already cycles `current_player_index` between hot-seat players and
recentres the camera on each empire's home colony, so the empire-focus
transition is a working concept — Event Log just doesn't follow it.

## Proposed fix path (not prescriptive)

1. Add `EventLog.get_events_for_empire(empire_id)` (or extend
   `get_all_events()` with an optional kwarg) that filters on
   `Event.empire_id`.
2. Plumb the active empire through `EventLogRegistrar.open_all()` (it
   has access to the facade and screen state already), so it passes
   `empire_id=current_empire.id` into the facade call.
3. `EventLogWindow` stores `empire_id` for redraws after category-filter
   changes.
4. Optional: surface the empire name in the window title bar
   ("Event Log — Chimera Empire") so the player can verify the filter
   is active.

## Acceptance

- A new game with ≥2 human empires shows only the active player's
  events in the Event Log.
- Cycling to the next empire (end-of-turn → next-player handoff) shows
  only that empire's events.
- The total event count visible in the Event Log decreases when the
  filter activates (regression evidence for tests).

## Priority

High — the bug breaks the multi-empire information model: each player
sees every other player's event stream including their colonisations,
production gating, and fleet movements. This is both an
information-leak problem (players see opponents' moves before they
should) and a usability problem (the log is cluttered with irrelevant
entries).
