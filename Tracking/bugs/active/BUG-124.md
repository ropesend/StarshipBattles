# BUG-124: Ship skin icons broken on strategy map for every ship theme — hardcoded filename mismatch

## Description

The user reports that the ship "skin views" on the strategy map are
broken regardless of which ship theme is selected. Fleets render as
plain coloured triangles (the missing-asset fallback) instead of the
themed ship sprite scaled down to icon size, and at least one
adjacent-hex element renders as a corrupted blocky thumbnail.

User commentary at QA Session 20260428_190154 [19:08:29 – 19:09:22]:
> "There's a problem with the skin views of the ships in the strategy
> map. Doesn't seem to matter which ship set it is."

[![Strategy map showing planet+fleet with fallback triangle and an adjacent-hex broken thumbnail](../../../tools/qa_observer/session_data/20260428_190154/images/bug_capture_190843.png)](../../../tools/qa_observer/session_data/20260428_190154/images/bug_capture_190843.png)

## Code investigation findings

**Root cause: hardcoded filename mismatch.**

[`game/ui/screens/race_asset_loader.py:248`](../../../game/ui/screens/race_asset_loader.py#L248):
```python
fleet_path = os.path.join(theme_path, "Skins", "Battlecruiser.png")
if os.path.exists(fleet_path):
    result['fleet'] = am.load_external_image(fleet_path)
```

The loader looks for `Skins/Battlecruiser.png` (PascalCase, no
underscore). Every ship theme on disk uses **`Skins/battle_cruiser.png`**
(snake_case). Verified across all 9 themes (`Aetherwake`, `Atlantians`,
`Federation`, `Klingons`, `Ossivine`, `Prismsteel`, `Romulans`,
`Thoraliens`, `Voidforged`):

```
assets/ShipThemes/Aetherwake/Skins/battle_cruiser.png
assets/ShipThemes/Atlantians/Skins/battle_cruiser.png
assets/ShipThemes/Federation/Skins/battle_cruiser.png
assets/ShipThemes/Klingons/Skins/battle_cruiser.png
... (and so on for all themes)
```

`os.path.exists()` returns `False` for every theme, so `result['fleet']`
is never populated. Downstream at
[`game/ui/screens/strategy_render/fleets.py:30-75`](../../../game/ui/screens/strategy_render/fleets.py#L30-L75)
the code falls back to drawing a coloured triangle in `emp.color` —
which is exactly what the screenshot shows on top of the planet.

The `'colony'` flag path on the line above
([line 243](../../../game/ui/screens/race_asset_loader.py#L243),
`Flags/Colony_Flag.jpg`) is also worth verifying — same hardcoded
single-filename pattern, same risk.

## Why "doesn't seem to matter which ship set it is"

The bug is in the loader, not the assets. **Every theme** ships the
file under the same snake_case name, so the loader fails identically
for all of them. Switching themes can never fix it.

## Proposed fix path (not prescriptive)

1. Change the hardcoded filename to `battle_cruiser.png` (matches the
   on-disk convention used by every theme and matches the snake_case
   naming used elsewhere in the codebase, e.g. `escort.png`,
   `light_cruiser.png`, `heavy_cruiser.png`).
2. Verify the colony flag path at the same time
   (`Flags/Colony_Flag.jpg` — confirm spelling and casing match disk).
3. Add a regression test that loads the asset for at least one theme
   and asserts `'fleet'` is in the result dict, so a future filename
   convention change can't silently re-break this.
4. Consider promoting the choice of "icon ship class" out of a
   hardcoded constant into theme metadata (`theme.json`), so themes
   without a `battle_cruiser.png` (future custom themes) can declare a
   different icon class.

## Acceptance

- A new game with any of the 9 stock themes shows fleet sprites on the
  strategy map (scaled-down theme `battle_cruiser.png`), not the plain
  coloured triangle.
- A regression test in `tests/unit/ui/screens/test_race_asset_loader.py`
  asserts the fleet asset loads successfully for at least one stock
  theme.

## Priority

Medium — the strategy map is fully usable (the fallback triangle
renders cleanly and uses empire colour for differentiation), but the
themed ship-art experience the player chose is silently absent from
every game.
