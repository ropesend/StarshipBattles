# BUG-109: Resources decline each turn despite large production surplus — eventual total maintenance failure

## Description
Resources (particularly metals) decline each turn despite the treasury showing a large net positive surplus (e.g., ~32k metals production vs ~5k maintenance). Over several turns, resources steadily drain until a mass "Maintenance Failure" event fires, scuttling all facilities at once.

The treasury panel shows production figures that should result in resources approaching maximum storage, but actual storage values drop turn over turn. This is not explained by storage caps (resources are well below max), construction costs (nothing was under construction), or cascade effects.

Something in the turn processing pipeline is either miscalculating production, over-deducting costs, or failing to credit harvested resources correctly. This bug requires a comprehensive deep-dive code review of the entire resource pipeline — harvesting, maintenance deduction, storage crediting, and turn tick processing — to identify the root cause.

### Deep Investigation Note
This bug should be investigated using multiple parallel agents performing a complete code review of the resource pipeline. Surface-level analysis has not identified the cause.

### Code Path Trace
```
UI (StrategyScreen) -> StrategySessionFacade.process_turn()
  -> GameSession.process_turn()
    -> TurnEngine.process_turn(empires, galaxy, save_path)
      -> Loop 100 ticks:
        Phase 0:  HarvestingEngine.process_harvesting_tick()
          -> recalculate_storage() [resets empire.max_storage from facilities]
          -> _process_empire(tick_fraction=0.01)
            -> For each colony/facility/harvester:
               harvest = base_rate * quality * 0.01
               actual = min(harvest, planet_quantity)
               empire.add_resources(resource_type, actual)
        Phase 0a: MaintenanceEngine.process_maintenance_tick()
          -> For each facility/ship:
             cost = total_build_cost * 0.05 * 0.01
             if empire.has_resources(cost): consume
             else: scuttle immediately
        Phase 0b: ResourceManagementEngine (ship-only, not empire pool)
        Phase 0c: ResupplyEngine.process_fuel_generation (facility fuel, not empire pool)
        Phase 0d: ResupplyEngine.process_fleet_resupply (ship fuel, not empire pool)
        Phase 0e: ProductionEngine.process_construction_tick()
          -> Consumes empire resources per construction queue items
        Phases 1-4: Orders, movement, combat (no empire resource changes)
      -> PopulationEngine.process_population_growth()
```

### Dependency Map
**Empire resource pool is modified by exactly 3 engines:**
1. `HarvestingEngine` — ADDS resources (empire.add_resources)
2. `MaintenanceEngine` — DEDUCTS resources (empire.consume_resources)
3. `ProductionEngine` — DEDUCTS resources (empire.consume_resources)

**EmpireEconomyCalculator** — READ-ONLY, creates snapshots for Treasury UI display. Does NOT modify game state.

### Similar Patterns Found
- EmpireEconomyCalculator.`_aggregate_colony_production()` uses `base_rate * quality` (per turn, no tick_fraction)
- HarvestingEngine._harvest_resource() uses `base_rate * quality * tick_fraction` (per tick)
- These are consistent: 100 ticks × 0.01 = 1.0 full turn

## Hypothesis Log

### Hypothesis 1: Planet resource quantity depletion — CONFIRMED
**Theory:** The treasury shows inflated production because `EmpireEconomyCalculator._aggregate_colony_production()` computes `base_rate * quality` without checking planet resource `quantity` remaining. When the planet's finite resource deposits deplete to zero, the harvesting engine produces nothing, but the treasury still forecasts full production.
**Evidence For:**
- Diagnostic logs confirm: once resources start declining, "AFTER HARVEST" values are identical to "TURN START" — **zero harvest**
- With 6 metal harvesters at quality ~50, per-turn harvest = ~30,000 metals. Planet quantity starts at ~500,000. Depletion in ~17 turns matches observed behavior exactly.
- Metals depletion happens first (highest harvest rate), then Organics, then Vapors — staggered exactly as expected from different quality values.
- Per-turn decline = ~5,658 metals = exactly the maintenance cost, confirming harvest is zero.
**Evidence Against:** None — fully confirmed by logs.
**Result:** ROOT CAUSE CONFIRMED.

### Hypothesis 2: Maintenance costs higher than displayed - REJECTED
**Theory:** Maintenance costs accumulating across turns.
**Result:** Logs show consistent per-tick maintenance of -10.2 metals (= 1,020/turn). This matches the treasury display. No accumulation.

### Hypothesis 3: Harvesting engine not finding harvesters - REJECTED
**Theory:** Registry lookup failing for harvester components.
**Result:** Harvesting worked correctly for ~17 turns, producing ~30,000 metals/turn. The registry lookup is fine. Production stops only when planet quantity hits zero.

### Hypothesis 4: Unknown resource consumer - REJECTED
**Theory:** Hidden resource consumer not in forecast.
**Result:** Logs show resource changes only in harvest and maintenance phases. No phantom consumers.
